## Expanding the ESLint configuration

If you are developing a production application, we recommend updating the configuration to enable type-aware lint rules:

```js
export default defineConfig([
  globalIgnores(["dist"]),
  {
    files: ["**/*.{ts,tsx}"],
    extends: [
      // Other configs...

      // Remove tseslint.configs.recommended and replace with this
      tseslint.configs.recommendedTypeChecked,
      // Alternatively, use this for stricter rules
      tseslint.configs.strictTypeChecked,
      // Optionally, add this for stylistic rules
      tseslint.configs.stylisticTypeChecked,

      // Other configs...
    ],
    languageOptions: {
      parserOptions: {
        project: ["./tsconfig.node.json", "./tsconfig.app.json"],
        tsconfigRootDir: import.meta.dirname,
      },
      // other options...
    },
  },
]);
```

You can also install [eslint-plugin-react-x](https://github.com/Rel1cx/eslint-react/tree/main/packages/plugins/eslint-plugin-react-x) and [eslint-plugin-react-dom](https://github.com/Rel1cx/eslint-react/tree/main/packages/plugins/eslint-plugin-react-dom) for React-specific lint rules:

```js
// eslint.config.js

import reactDom from "eslint-plugin-react-dom";

      // Enable lint rules for React

      // Enable lint rules for React DOM
      reactDom.configs.recommended,
    ],

        project: ["./tsconfig.node.json", "./tsconfig.app.json"],
        tsconfigRootDir: import.meta.dirname,

    },
  },
```

# Print Job Automation System

A full‑stack application for managing print jobs across multiple departments (Knitting, Legal, IT, Mechanic, Technician).

> **MongoDB**: This project is backed by **MongoDB Atlas** (via `pymongo`). Create a `server/.env` file using `server/.env.example`.

## Features

- Create print jobs with user ID, document name, pages, copies, and department.
- Automatically routes jobs to an available printer in the correct department.
- Dashboard shows all jobs, filterable by status and department.
- Print and delete actions with confirmation.
- Stores all job history in MongoDB (MySQL schema also provided).

## Tech Stack

- **Frontend:** React 19, TypeScript, Vite
- **Backend:** Flask 2, pymongo
- **Database:** MongoDB Atlas (primary), with optional MySQL schema

## Getting Started

### 1. Clone and set up backend

```bash
cd server

# Create env file for MongoDB Atlas
copy .env.example .env  # Windows
# (Or) cp .env.example .env

python -m venv venv
venv\Scripts\activate
pip install -r requirments.txt

# Seed printers (only runs if printers collection is empty)
python seed_100_printers.py

# Start server
python app.py

```

# Print Job Automation System

A full‑stack print job manager that mimics a Ricoh printer dashboard.  
Built with **React + TypeScript** frontend and **Flask + MongoDB** backend, secured with an API key.

## Features

- Create print jobs (user, file, pages, copies, department)
- View jobs filtered by status (pending / printed / deleted) and department
- Simulate printing (update status to `printed` with timestamp)
- Delete jobs (soft delete → status `deleted`)
- API key authentication for all backend endpoints

## Tech Stack

- **Frontend:** React 19, TypeScript, Vite
- **Backend:** Flask, PyMongo, Flask-CORS
- **Database:** MongoDB Atlas (or local MongoDB)
- **Auth:** API Key (sent via `X-API-Key` header)
